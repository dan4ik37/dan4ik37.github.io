# Mini-games on ArcadeKit (T-140) — porting recipe

Shared core: `js/games/arcade/core.js` (`ArcadeKit`). Reference games: `tiles` (canvas, «Чёрные плитки») and `lights`
(DOM, «Свет в окнах»). Read both before porting — copy the closer one.

## What one game is (all new files — no conflicts between parallel agents)

| File | What |
|---|---|
| `js/games/arcade/<id>.js` | the game: pure simulation + drawing, one `ArcadeKit.define('<id>', spec)` call |
| `js/games/arcade/<id>.json` | catalog card, SEO page, rules, server keys (see «Card») |
| `scripts/arcade/<id>.cjs` | node bot + scenarios for `arcade-test.cjs`, Chrome bot for `arcade-e2e.cjs` |

`id`: 2–16 lowercase latin letters, no `_`, no digits (it is the server key; `game_family` in economy.sql cuts at `_`/digits).

## Integration-only files — never hand-edit

`js/features/games.js`, `api/_lib/age.js`, `api/_lib/games-seo.js`, `games-more.sql`, `img/games/_make-cards.py`, sitemap
(automatic from GAME_PAGES). The regions between `⟦arcade⟧ … ⟦/arcade⟧`, `api/_lib/games-seo-arcade.js` and
`js/games/rules-data.js` are generated by `node scripts/make-arcade.mjs` from every `<id>.json`. Run it to test your game
locally (it adds the catalog entry), commit its output in a separate last commit. Merge conflict in a generated region /
file: take either side, rerun `node scripts/make-arcade.mjs`, `git add`. `GAMES_VER` — the coordinator bumps it at merge.
Preview PNG: `python -X utf8 img/games/_make-cards.py <id>` (commit `img/games/<id>.png`). CI: `make-arcade.mjs --check`.

Never touch: `js/engine/model.js`, `js/apps/ai3d/*`, `kubomir*`, `support.js`, `versus.js`, `room.js`, `core.js` (core changes
go through the coordinator — tell them what you need).

## File skeleton

```js
// ═══ ИГРА «НАЗВАНИЕ» (T-140) — одна строка: что делать. Одиночная или «⚔️ Соревнование» ═══
// Ядро — js/games/arcade/core.js (docs/ARCADE.md). Поле W×H, скорости — в долях/единицах поля за секунду.
// Своё (твист): … Исправлено против прототипа: … (list every prototype bug you fixed)
(() => {
  const T = ArcadeKit.T;
  const W = 320, H = 440;                     // logical field units (canvas draws in them; the kit scales to DPR)
  function create(rng, opt){ /* typed arrays / fixed rings allocated HERE once */ return s; }
  function input(s, e, inp){ /* e.type: T.DOWN/MOVE/UP (e.x, e.y in field units), T.KEY/KEYUP (e.k), T.PICK (e.k = data-k) */ }
  function step(s, dt, inp){ /* one fixed step, dt = 1/60 s; inp = { down, x, y, keys } */ }
  function draw(G, s, alpha){ /* canvas: G.ctx in field units; interpolate prev→cur by alpha */ }
  ArcadeKit.define('<id>', {
    kind: 'canvas', W, H,                     // or kind: 'dom' + build(G, s) — G.host is the field element
    title: '🎯 Название', intro: 'Rules in 1–2 sentences (start overlay)', controls: 'Touch / mouse / keys line',
    duelTitle: 'Одинаковые … у обоих',
    keys: { KeyA: 0, ArrowLeft: 0, Space: 1 }, // e.code → ev.k (and inp.keys bit k); omit if none
    drag: false,                              // true → also MOVE / UP events (pointer capture)
    create, input, step, draw,
    hudKey: s => /* number */, hud: s => /* string; called only when hudKey changes */,
    win: s => /* «good result» → XP */, result: s => ({ title, text }),
    consts: { /* numbers the test bots need */ },
  });
})();
```

State contract: `s.score` (number, **bigger is better** — convert «fewer moves/seconds» into points), `s.over` (true ends the
run), `s.snd` (sound request: `'ok' | 'bad' | 'win' | 'tick' | 'move'` or an **integer** Hz for a tone; the kit plays and
clears it), `s.v` (DOM games: bump when the field must be redrawn).

## Rules (each is checked by the tests)

- **Pure simulation.** `create/input/step` use only `s.rng` given to `create` — no `Math.random`, `Date`, `performance`,
  DOM, timers. Time = steps (`s.left = 120 * 60` for 2 minutes). Speeds are per second × `dt`. Positions in field units or
  fractions. The ⚔️ opponent gets the same seed → the same game; screen size must not matter.
- **Every run ends**: by failure or by a time limit (competition needs both players to finish). No endless puzzles.
- **Input** is an event queue applied at step boundaries by event time (frame-rate independent). Resolve taps by the cell
  *under the finger* (row and column), give a small tolerance, forgive taps before the run really starts, never end the run
  on the very first tap. Keyboard: map keys in `keys`; DOM buttons work with Tab + Enter through `click`.
- **Two thumbs** (check T-140 D1): browsers fire NO `click` for overlapping multi-touch taps, so the kit never relies on it
  for pointers. DOM `pick: 'tap'` (default) counts a press at `pointerup` of that finger (a swipe that scrolls the page —
  `pointercancel` — or a finger slid off the button is not a press); `pick: 'down'` counts at `pointerdown` — use it when
  the ORDER of fast presses matters (notes, pop-it): with 'tap' two overlapping thumbs count in release order.
- **Skill, not luck or idleness** (check T-140 R1, D2–D4): a run with no input (the game acting by itself — auto-drop,
  auto-pour) scores 0 and is never a win; tapping blindly / at random (as fast as allowed, and at a human tempo) must score
  clearly less and win clearly less often than a strategy bot at the same tempo. Add a scenario that proves it (pegs, pour,
  parking, planets have one).
- **No garbage per step/frame**: typed arrays, fixed rings, preallocated pools created in `create`; no `{}`/`[]`/closures/
  `filter/map/forEach`/template strings in `step`/`draw`. Strings for canvas text: constants, or cache on `G`
  (`if (G.sc !== s.score) { G.sc = s.score; G.scT = String(s.score); }`). `draw` only reads `s`.
- **Canvas**: draw in field units, colours as constants or `G.theme` (games are dark islands — `#gamesStage` keeps dark
  tokens in both themes). Nothing over the play field except the start / pause / result overlay of the kit.
- **DOM**: build the field in `build(G, s)` (once per state; inject game CSS once: `<style id="<id>Css">`, classes prefixed
  with the id), update in `draw` only when `s.v` changed, use `classList.toggle(name, on)`, user text only via `textContent`
  (games here have no foreign text). Elements that are pressed carry `data-k="<index>"`.
- **Do not** add listeners on window/document, timers, rAF, AudioContext — the kit owns them (pause on hidden tab, resize,
  keys, unmount cleanup, one shared AudioContext). If you think you need one, ask the coordinator.
- **Originality** (owner red line + coordinator): genre mechanics are fine, but no original titles, characters, signature
  item chains, art or level layouts of commercial games, never named in title/desc/SEO. Own name, theme and at least one
  small twist. No paid randomness, no casino imitation (no bets, coins or wager multipliers). Age 0+, kids-safe visuals.
- **Mobile first**: big targets (≥ 44 px on a 360 px wide phone), one-hand play; HUD = the kit's two short rows above the
  field (score · record, then your `hud(s)` line across the whole width, ≥ 340 px): keep `hud(s)` within ~320 px —
  `arcade-e2e` measures every string your bot produced on a 360-px phone with the game's score cap.

## Card `js/games/arcade/<id>.json`

(comments only in this example — the real file is plain JSON)

```json
{ "id": "tiles", "icon": "⬛", "title": "Чёрные плитки", "color": "#e5e7eb",
  "desc": "Catalog text, 1–2 sentences, mentions the ⚔️ friend mode",
  "tags": "new mini friends action",                       // + brain for puzzles, action for arcade
  "unit": ["очко", "очка", "очков"],                       // record label: 1 / 2–4 / 5+
  "server": { "cap": 20000, "capDuel": 20000, "xp": 4, "xpDuel": 5 },
  "seo": { "title": "…", "h1": "…", "description": "…", "lead": "…", "features": [], "rules": [], "tips": [], "faq": [["q", "a"]] } }
```

`cap` — the highest honest score (server rejects more); XP like similar games in `game_win_xp` (quick/arcade 4 / duel 5,
very short 2 / 4; coins — none, amounts are owner-only). `seo.rules` + `seo.tips` are also the 📖 «Правила» window.
Texts in Russian, simple words; the 📣 challenge link and the preview page come from this card automatically.

## Competition (⚔️) and records — free from the kit

`/games/<id>/<code>` → `Versus.start` → the kit builds the same shell with the host's rng; score goes live to the opponent
(`hooks.progress`), `hooks.done` at `s.over`; result `<id>_duel` only if both finished. Solo: new seed per run, `api.report
(id, win(s), score, score)`, best in the HUD, «↻ Ещё раз», «⚔️ Соревноваться с другом».

## Test recipe

1. `scripts/arcade/<id>.cjs` (copy `tiles.cjs` / `lights.cjs`): `bot(K, spec, gap)` → `(s, step, push)` called before every
   step, `push(type, x, y, k)`; `maxMs`; `garbage: { gap, ms, repeat }`; `scenarios(K, spec, ok)` — call `spec.create /
   input / step` directly: expected score for a scripted input, every prototype bug you fixed as a regression, run end
   (by failure and by time); `e2e: { bot(gap, stopAfter) → JS string that sets window.__bot, gap, stopB, endByStop, endMs,
   field, before?, after? }`.
2. `node scripts/arcade-test.cjs <id>` — bot at 30/60/144 FPS identical; recorded taps with times between steps replayed at
   30/60/144 identical; same seed = same game; no Math.random/Date; scenarios; allocations: logic < 8 B/step, drawing — only
   boxed numbers for canvas calls. Report its numbers line.
3. `node scripts/make-arcade.mjs` then `node scripts/make-arcade.mjs --check`.
4. `node scripts/arcade-e2e.cjs <id> 12` (headless Chrome, phone 412×915, CPU ×4, own server, two browsers for ⚔️ through
   the real Supabase Realtime): start does not end the run, pause on hidden tab, step+draw p95 < 3 ms / p99 < 8 ms, result
   + record + «↻ Ещё раз», 20 open/close without listener / node / memory growth, ⚔️ same field, live opponent score, result
   on both sides. Look at 2–3 screenshots in `E:\claude-tmp\<task>\shots` (start, play, result).
5. Report numbers from 2 and 4 (perf, leak, duel) — no numbers, not accepted.
