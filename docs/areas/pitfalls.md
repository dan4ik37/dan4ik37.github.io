- Python со строками по-русски — только `python -X utf8 script.py`; сложные правки писать файлом-скриптом через
  Write, а не heredoc в bash (bash-heredoc с кавычками/`$` в этой среде падает с «unexpected EOF»).
- В скриптах правок `s.replace(a, b)` со строкой b — знаки доллара в b особые (двойной доллар, доллар+апостроф, доллар+&):

- `classList.add/remove` пишут атрибут class даже без перемены: если MutationObserver смотрит на class этого же места — вечный
  цикл каждый кадр (так было с пилюлей меню в fx.js, ≈ 1 мс на кадр в играх на телефоне). Только `classList.toggle(имя, вкл)`.

- Экранирование вида \u2028 / \u200b внутри текста, который пишется через Write или heredoc, превращается в НАСТОЯЩИЙ
  символ (U+2028 — это перенос строки: регулярка ломается, файл не грузится). Такие символы собирать через
  String.fromCharCode, а файлы после записи проверять `node --check`.
- В шейдерах Three.js `#include <…>` — только с новой строки (в одну строку шейдер не собирается).
- GLSL в Chrome на Windows (ANGLE → Direct3D): не передавать сэмплер параметром функции во вложенном вызове
  (`tx(tMat, int(tx(tTri, i).w))` читал не ту текстуру — без ошибок, просто неверно) — своя функция чтения на каждую текстуру;
  `out`-параметр, не записанный на каком-то выходе, затирает значение у вызывающего — для «запомни, если нашёл» только `inout`.

- **Телефоны и точность (15.10.2026, «пятна» на площади и фонтане у владельца).** У `sampler2D` во фрагментном шейдере
  точность по умолчанию lowp, а значение из текстуры приходит С ТОЧНОСТЬЮ СЭМПЛЕРА: на телефонах (Adreno, Mali, Apple) —
  fp16. three r149 точность сэмплеров не задаёт. Глубина, упакованные данные, float-таблицы — только через highp-сэмплер:
  в постобработке — строка `E.POST_PREC` в начале шейдера (mk() в post.js ставит её сам), в своих кусках three —
  `E.SAMPLER_PREC.hi … .lo` (gfx.js). На компьютере (ANGLE/D3D) всё fp32 — на нём такую ошибку НЕ видно. Проверять
  подменой: обернуть чтения в `unpackHalf2x16(packHalf2x16(…))` — так телефон видит текстуру. Телефон — `E.isMobile()`
  (не по одной строке браузера: «версия для ПК» и iPad пишут себя компьютером).

- **Утечки при закрытии игры (T-085, «Мир Денчика» держал каждый прошлый мир: 77 → 350 МБ за 10 входов).** Что держит прошлое:
  (1) свой геттер у объекта, который создаётся заново на каждый мир (`get x(){}` в объекте внутри функции, `Object.defineProperty(o,
  'x', { get })`, класс с геттерами внутри функции) — V8 хранит его в общей «форме» объекта (AccessorPair) и держит последний
  экземпляр, а с ним весь мир; можно — геттер общего прототипа уровня модуля (`class` на уровне файла, `Object.create(PROTO)`) или
  поле; (2) слушатель на том, что живёт дольше игры (#gamesStageBox — рамка, в которую монтируют, #gamesStage, window, document) и
  подписка без отписки (`D37Age.on` — храни off); (3) данные модуля с вещами мира (TABLES[i].tag, BUILT); (4) общие на страницу вещи
  three (геометрия спрайтов, карта погоды GFXU.occRT): каждый рендерер вешает на них «dispose» — render.js R.dispose их dispose'ит;
  (5) Supabase держит снятый канал и его обработчики ещё ~10 с — обработчики не должны замыкать состояние мира (своя функция уровня
  модуля, как mir.js openChannel, или «реле» с off(), как mir-war.js relayChannel). Проверки: `node scripts/world-leak-test.cjs` (node:
  дерево JS мира — п. 1–2 и места выше) и `node scripts/world-reopen-e2e.cjs [N] [pc|phone]` (Chrome: N раз закрыть/открыть, в дождь;
  WeakRef на мир и контекст WebGL, куча после сборки мусора, слушатели, таймеры, каналы). Как искать новое: снимок кучи после 1-го
  закрытия и после N-го, объекты новее первого снимка, ещё достижимые, — путь от корней, рубить ребро «старое → новое»
  (так найдено всё выше; DevTools → Memory → Comparison / Retainers делает то же руками).
