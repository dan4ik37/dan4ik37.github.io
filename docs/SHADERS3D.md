# Шейдеры 3D — наборы картинки движка (как наборы шейдеров для Майнкрафта, но свои)

Модули: `js/engine/gfx.js` (данные наборов, LUT, небо v2, ветер, вода v3), `js/engine/post.js` (сборка кадра наборов, лучи,
глубина резкости, страж графики), `js/engine/render.js` (`R.applyPack`, `R.wave`). Работает во всём, что рисует через
`D37E.renderer`: «Мир Денчика», «Студия 3D», набеги 3D, «Кубомир». 2D-наборы — `js/engine/shade2d.js` (docs/SHADERS2D.md).

## Наборы и настройка

Игрок выбирает в **⚙️ → Графика → «Шейдеры»**. Ключ настройки общий с 2D — **`shaders`** (`auto | normal | pretty | ultra |
toon | retro`), на живую — `D37Opt.gfx.shaders`; «Полоски CRT» у «Ретро» — **`crt`**. Смена набора — на лету, без пересборки мира.

| Набор | Что даёт | Цена (RTX 5060 Ti, видеокарта на кадр) |
|---|---|---|
| **Авто** | как у 2D: пресет «Ультра» → «Ультра», «Высокая» → «Красивые», «Низкая»/«Средняя» → «Обычные»; пресет «Авто»/«Своя» — по устройству: телефон — «Обычные» (сильный — Adreno 730+, Mali-G710+/Immortalis, Xclipse, Apple, 6+ ядер — «Красивые»), компьютер с высокой основой — «Красивые» | — |
| **Обычные** | как было до наборов — ни одного нового куска шейдера не собирается (сборка кадра — прежний текст до буквы) | как раньше |
| **Красивые** | тон AgX «сочный» (мягче к ярким, как в кино) и цвет набора (LUT 32³), лучи солнца и луны сквозь листву и окна (¼ кадра, 24 шага), облака слоем по небу, заря и второй слой звёзд, трава и листва на ветру, вода с каустикой по дну, под водой — тон и колыхание, свечение ×1,25 | ≈ как «Обычные» (разница в шуме замера ±0,2 мс; 1080p ~1,7 мс, 4K ~6 мс) |
| **Ультра** | всё из «Красивых», лучи — ½ кадра, 40 шагов, два слоя облаков (кучевые + перистые, 5 октав), глубина резкости (фокус — свой персонаж), свечение ×1,4. На телефоне — лучи и облака ступенью ниже, без глубины резкости | +0…0,3 мс |
| **Мультяшные** | свет полосами (по сглаженной яркости — рисунок текстур не рвётся), чёрные контуры по излому глубины, сочные цвета | +0,2…0,4 мс |
| **Ретро/пиксели** | кадр в 3 раза крупнее пикселями (без сглаживания), цвет полосами (HSV: 24 оттенка, ступени насыщенности и яркости); по желанию — полоски CRT | дешевле «Обычных» (кадр в 9 раз меньше) |

Автокачество (пресет «Авто») снимает дорогое набора первым: без лучей и второго слоя облаков → без облаков слоем и ветра.

## Как устроено

- Набор — **данные** (`E.PACKS`), не код: `tone` (aces/agx), `look` (экспозиция, «сочность» AgX, насыщенность, контраст, тепло,
  сплит-тон), `bloom`, `halo`, ступени `rays`, `clouds`, флаги `sky`, `wave`, `water`, `under`, `toon`, `retro`, `dof`.
  `E.packResolve(want, dev)` → что включить на этом устройстве; `E.packSanitize(d)` — набор из данных мира или мода (только
  известные поля в пределах, GLSL от игроков — никогда).
- Тон AgX — без пересборки материалов: материалы рисуют с ACES, как раньше; LUT сборки кадра возвращает значение через
  обратный ACES (точно: дробь ACES обращается корнем квадратного уравнения) и пропускает через AgX (Трой Собетка; вариант
  Filament / three.js — MIT, Apache-2.0) и цвет набора. LUT печётся в JS (`E.packLUT`, 10–60 мс при смене набора).
- Всё новое — **под define**: сборка кадра `D37_LUT / D37_RAYS / D37_TOON / D37_RETRO / D37_CRT / D37_UNDER / D37_DOF`, небо
  `D37_SKY2`, материалы `D37_WAVE` (ветер), вода `D37_WATER3`. У «Обычных» этих define нет — программы те же, что до наборов.
- **Страж графики** (`E.gfxGuard`, docs — CLAUDE.md): программа набора не собралась (сборка с кусками набора, лучи, глубина
  резкости, материал с ветром / небом v2 / водой v3) или кадр набора гаснет → набор запоминается как «не работает здесь»
  (`d37_gfx_guard`, ключ `pack:<id>`) и включается предыдущий (ultra → pretty → normal; toon, retro → normal). В ⚙️ — «На этом
  устройстве не заработали: …». Сообщение — `gfx_fallback { what: 'pack:ultra', why, prog, gpu }`.
- Телефоны: все сэмплеры постобработки — highp (`E.POST_PREC`); проверено подменой чтений на половинную точность
  (packHalf2x16) и в Chrome на SwiftShader / Vulkan / OpenGL (`node scripts/gfx-strict.cjs swiftshader high 1 pretty`).

## API для игр («Кубомир», набеги 3D, свои миры)

Всё работает само, если игра рисует через `R = D37E.renderer(...)` и `R.render()`: сборка кадра, лучи, LUT, глубина резкости,
небо v2 и облака. Своим материалам — по желанию:

```js
R.wave(material, { kind: 'grass', h: .5 });   // трава: верх качается (h — высота кустика в единицах модели)
R.wave(material, { kind: 'leaves' });         // листва: крона чуть «дышит»
// без R (материал заранее): E.waveMaterial(m, { kind }) — R подхватит его при смене набора
R.bloom(material, 1.2);                       // светится (факелы, лава, неон): свечение набора × сила
R.lights.add({ position, color, intensity, distance });   // настоящий свет + ореол (наборы делают ореол ярче)
R.water(color, { depth: { tex, rect } });     // вода v2 → v3 у наборов (каустика по дну — по карте глубины)
R.packFx();                                   // что сейчас включено: { id, tone, rays, clouds, wave, water, toon, retro, dof, … }
// своя вырезка по альфе (листья, трава, цветы) — код травы для AO (без тёмных пятен вокруг):
// uniform vec4 d37Rt = { value: E.GFXU.rt }; после #include <output_fragment> — E.FOLIAGE_GLSL
```

Свои шейдеры игры: новое — тоже под define, который можно снять; `smoothstep` — только edge0 < edge1; в `gl_FragColor` —
целым вектором без `if`; в циклах — `textureLod`, без `continue`/`texelFetch`; «не число» — по битам, не `isnan()`.
