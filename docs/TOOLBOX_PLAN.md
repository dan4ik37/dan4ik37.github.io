# План «🧰 Набора» и заготовок игр для «Студии 3D»

Агент изучил код 11.10.2026 и остановился по просьбе владельца до того, как начал писать. Ниже — что он выяснил и в каком
порядке делать. Код ещё не начат.

## Как подключать

- Новые файлы студии — в массив `scripts` записи `studio3d` в `js/features/games.js` и поднять `GAMES_VER`. Ту же строку
  правят и другие агенты (инструменты, ИИ) — при слиянии будет конфликт, он простой.
- Расширение работает и до, и после загрузки `studio3d.js`: студия берёт уже готовый массив `D37E.studioExt`.

## Новый мир для заготовки игры

- В `STUDIO_API` нет вызова «новый мир» и «сохранить».
- Обработчик меню студии ловит любой элемент `[data-m]` внутри `.s3`. Значит, можно добавить скрытую
  `<button data-m="new:empty">` и нажать её `.click()`. Это настоящий путь студии: текущий мир сохраняется, создаётся
  новый `placeId`.
- Дальше: дождаться, пока сменится `api.ed.placeId` и закончится сохранение. Потом `pushHist`, построить заготовку,
  вписать имя в `.s3-name` и нажать `data-m="save"`.
- Запасной путь: `pushHist` и замена текущего мира. Отмена вернёт только объекты, а не ландшафт и свет.

## Правила сцены

- Тело детали точное только при повороте по Y и шагах по 90° по X/Z. Остальные наклоны становятся описанной коробкой,
  поэтому наклонные украшения ставить с `collide: false`.
- Клин: низкий край — локальный +z, высокая грань — −z. Цилиндр: ось вдоль Y.
- Повернуть весь предмет на yaw: x' = x·cos + z·sin, z' = −x·sin + z·cos, к `rot[1]` прибавить yaw.

## Касания без кода

- `kill`, `bounce`, `speed`, `coin`, `finish` работают как есть. Точка появления — чекпоинт.
- Касание срабатывает и у непроходимых деталей, поэтому монетки можно делать `collide: false`.

## Ограничения скриптов

- `Instance.new` умеет только Part, WedgePart, SpawnLocation, PointLight и Model (плюс объекты-значения).
- Скрипт не может менять `touch` и `enabled`, то есть не может включать и выключать эффекты и касания.
- `player.Teleport` обнуляет скорость, поэтому конвейер телепортом не сделать.
- `Completed` у TweenService работает через событие `tweenDone`.

## Цифры игрока

Единица — 1/`D37E.UNIT` м.

- Прыжок — 1,4 ед. в высоту.
- Ходьба — 4,67 ед./с, бег — 8,17 ед./с.
- Прыжок с места в длину: шагом ~3,2 ед., с разбега ~5,7 ед.
- Ступенька — 0,62 ед.
- Батут подбрасывает на ~5,8 ед.

## Конвейер и двери

- Игрока везёт деталь под ногами, поэтому конвейер — это планки, которые двигаются каждый Heartbeat. По краям — валики
  выше планок, под ними планки перескакивают в начало. Иначе перескочившая планка утянет игрока назад.
- Дверь на петлях: твинить отдельно `Position` и `Orientation`, а не `CFrame` (иначе угол может пойти «длинным путём»).
  Петля — на локальном −X; yaw `a` переводит локальный +X в (cos a, 0, −sin a).

## Значки предметов

- Отдельный маленький offscreen-WebGL со своим светом окружения. Карту окружения основной сцены взять нельзя: она
  принадлежит другому контексту WebGL.
- Сцена для значка — `E.scene(R2, ph2)`, где `R2 = Object.create(ed.R)` со своей сценой. Подключить `E.fx` и
  `E.npcs`, чтобы были видны огонь и NPC.
- Перед рисованием дождаться загрузки картинок текстур.
- Кэш значков — IndexedDB: ключ = хэш описания предмета + номер версии. Рендерер освобождать после каждой пачки.

## Куда ставить предмет

- Луч по сеткам объектов (кроме ламп, эффектов, NPC) и `ed.ph.raycast` (земля, ландшафт).
- Если появится `D37E.tools?.placeOnSurface` от агента инструментов — вызывать его в try/catch и проверять результат.

   - `cats()`, `list()`, `get(id)`;
   - `blueprint(id, { at, yaw, scale })` — узлы простыми данными;
   - `build(id, { at, yaw, scale, SC, parent })` — один корень без обёртки, несколько корней — в Model;
   - `kits()`, `buildKit(id, { SC, TR, R })`;
   - `describe()` — для ИИ-помощника.

   В черновике ~82 предмета:

## Модели Kenney (CC0, владелец разрешил 11.10.2026 — ещё не начато)

- Тип предмета `mesh` с `src` на статический `.glb` в репозитории (например `models/lib/<пак>/<имя>.glb` + License.txt пака).
- При первой постановке:
  1. скачать и прогнать через `D37E.models.compile([файл])` — `model.js` сам проверит и сожмёт;
  2. положить в IndexedDB под постоянным id `lib-<пак>-<имя>`, чтобы миры с этой моделью не ломались;
  3. вставить объект `Mesh` с `{ model: id, size }`.
- Значки — тем же offscreen-рендерером.
- **До публикации миров нужна правка в `studio3d.js`.** Сейчас «📤 Выложить» отправит такие модели как свои, на проверку.
  Нужно одно из двух: пометить библиотечные модели (`foreign`/`lib`) и пропускать их при выкладке — или научить
  `E.models.remote` брать `lib-…` со статического адреса, чтобы их видели и другие игроки.
