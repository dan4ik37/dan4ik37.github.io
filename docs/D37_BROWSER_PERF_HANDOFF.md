# D37 browser performance handoff

Build `6b816f9874` is published for testing at [/d37-preview/?world=worker&gpu_cull=1](/d37-preview/?world=worker&gpu_cull=1). Its browser save uses `d37.preview.game.*`. Start from engine branch `codex/gpu-m1`, commit `65954b8` and preserve the existing site build at `/d37/` and in the hub while validating the candidate.

## Verified changes and limits

- `12e9533` indexes NPC building obstacle queries and avoids inactive water spans. `cee346a` gives up to eight nearby characters exact visual foot IK and staggers ground sampling for the rest. `65954b8` keeps dry water tiles asleep until an event wakes them, limits cliff samples per tick from 240 to 96 and sends worker input updates when the state changes. This can delay distant cliff details. World commands and networking still run when input is unchanged.
- The local smoke reached a populated low-altitude Shift flight, a cave and a camp with 48 NPCs plus the player. The longer run retained construction and terrain edits through 25 minutes. Its final attempted flight at minute 25 failed the density assertion (50 of 68 samples had at least 1,000 scatter instances, below the 75% threshold). That is an open streaming or route issue. Trace biome and altitude, desired and resident tiles, queue age and evictions to distinguish them.
- In one 96-second low flight with 54,509 scatter instances at the end, rendering averaged 162 FPS with 12.1 ms p99 frames. The world executed 48.2 ticks/s and skipped 1,129 ticks. In a dense camp phase after edits it executed 18.6 ticks/s at 164.5 FPS. In that phase `~actor_animation` averaged 40.2 ms of the 50.3 ms worker tick. The earlier cave walk reached 60 ticks/s. The 30-minute acceptance, 10 simultaneous clients and a physical phone are still open.

## Next implementation

1. Start with `crates/d37-app/src/character.rs` and `sim.rs`. Split the timing of terrain support probes, collider queries, animation and held-item formatting. Reuse authoritative movement height, and cache extra visual support against changed terrain and colliders. Budget exact foot IK separately from NPC simulation. Headless authority should skip work used solely to draw NPCs. Compare the same camp with 48 NPCs, 45 structures and recent terrain edits.
2. In `crates/d37-web/src/worker.rs`, track actual TPS, excess tick debt, discarded wall time, input-to-apply and last snapshot age. At 60 Hz a tick has 16.67 ms. Keep local camera immediate and interpolate snapshots. Confirm placement, damage, pickups and saves at authoritative ticks. Avoid unbounded catch-up, since it delays input and masks the source of slow ticks. Exercise repeated Shift flight, orbit, a cave, saves and building for 30 minutes. Track CPU/WASM memory and GPU residency separately.
3. Profile `waterlive`, `landform`, `dig.water` and `fauna.find_water` during repeated flight. Keep settled state dormant until inputs change. Queue jobs by changed region and version, use a cheap nearby-water index, then run independent generation and queries on workers. For predictable movement store an epoch and trajectory, and recompute at an external change. Commit worker results in stable order and discard results whose region revision expired.
4. GPU work goes through `crates/d37-render`. Add wind in the existing scatter shaders from time, wind and a stable per-tree phase, with root position fixed and matching depth, shadow and color passes. Prototype GPU visibility and indirect draws for already resident instances, keeping near assets and a lower LOD resident until replacements are ready. Keep the WebGL2 path and verify mobile. Use GPU-only particles and cosmetic debris at scale. Collision, inventory and multiplayer commands depend on authoritative Rust state. Keep synchronous GPU readbacks out of the tick loop.

## Factorio techniques for D37 multiplayer

[Factorio's entity budgets and aggregation](https://factorio.com/blog/post/fff-148) and [ordered worker wake-ups](https://factorio.com/blog/post/fff-364) map to D37 sleeping water tiles, settled debris, and dirty cells. Research the current wake owners per region before adding a queue. Track active versus dormant counts and wake causes to catch missed wakes after digging, a collision, editing a building or crossing a chunk boundary.

Factorio uses deterministic lockstep and a separate prediction layer. D37 already has server authority, client prediction and per-cell digests in `crates/d37-app/src/authority.rs` and `crates/d37-net/src/auth.rs`. Reuse these paths. The current digest covers placed parts, positions, open and lit state. Before changing wire behavior, add diagnostics for server tick, cell revision, last applied command sequence, local and server digest, first mismatch tick, resync requests, corrections and queue ages. Compare equivalent confirmed revisions after acknowledgements. Separate a delayed snapshot from a mismatch at the same revision. Preserve a bounded command log and paired state slices for a dev-only replay. [Factorio prediction](https://www.factorio.com/blog/post/fff-302) · [Factorio desync reports](https://www.factorio.com/blog/post/fff-188)

Introduce a versioned digest only after testing coverage. Define canonical ordering and field encodings (including building rotations and placed-part state, then terrain edits and containers). Compare hashes incrementally for dirty cells, with separate scopes for seeded terrain, building state and inventories. Exclude render caches and transient prediction. Start with a replay of identical acknowledged commands on native and WASM at different render rates. Deliberately alter one cell to verify localisation and recovery, then test 10 clients at the same camp and spread across regions with latency, jitter and reconnects. Record actual server TPS, p99 tick time, bandwidth per peer, input delay, corrections, confirmed mismatches and successful resyncs. Promote the preview only after the long route and multiplayer/phone verification.
