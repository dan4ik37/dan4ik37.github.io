# Моды для игр сайта — общая спецификация

Моды добавляют в игру свои **блоки, предметы, рецепты, руды** (данными) и **поведение** (скриптами на JavaScript или Lua).
Одна спецификация на две игры сайта:

| Игра | `game` в mod.json | Где код |
|---|---|---|
| «Подземье» — песочница сбоку (#/games/podzem) | `"tiles"` | js/games/podzem-mods.js |
| «Кубомир» — кубический мир (#/games/kubomir) | `"voxel"` | js/engine/voxel-mods.js, js/games/kubomir-mods.js; особенности — раздел 7 |
| обе | `"both"` | мод подходит обеим: каждая игра берёт то, что понимает |

Общая часть (формат файла, поля mod.json, API скриптов версии 1, ограничения) — **одинаковая в обеих играх**: меняется
только по согласованию, новое — только добавлением (старые моды не ломаются).

---

## 1. Файл мода

- **`.d37mod`** — обычный zip-архив (можно переименовать `.zip`); внутри `mod.json`, скрипты и картинки. Общая папка верхнего
  уровня (`мой-мод/mod.json`) допускается.
- **Папка** с `mod.json` (в игре — «📁 Из папки»).
- **Один `mod.json`** — если скрипты лежат в нём строкой (`"code"`), а картинки — `data:image/png;base64,…` или «нарисованы» (`draw`).

Ограничения: до 8 МБ, до 200 файлов, картинки — до 2,5 МБ на мод, скрипт — до 200 КБ, скриптов — до 4.
Пути внутри архива — только вниз (`textures/ruby.png`; `..` и `/` в начале запрещены).

## 2. mod.json

```json
{
  "id": "ruby-glow",
  "name": "Светящиеся рубины",
  "version": "1.0.0",
  "game": "both",
  "api": 1,
  "author": "dan4ik37",
  "description": "Рубиновая руда светится красным. Пример мода на JavaScript.",
  "textures": { "ruby_ore": { "draw": { "pattern": "ore", "base": "#6f6f7a", "color2": "#e0204a", "color3": "#ffb0c0" } } },
  "blocks":   [ { "id": "ruby_ore", "name": "Рубиновая руда", "texture": "ruby_ore", "hardness": 180, "tier": 2, "light": "#901028", "drop": "ruby" } ],
  "items":    [ { "id": "ruby", "name": "Рубин", "texture": "ruby", "stack": 99 } ],
  "recipes":  [ { "result": "ruby_lamp", "count": 2, "ingredients": [["ruby", 1], ["torch", 2]], "station": "workbench" } ],
  "worldgen": [ { "type": "ore", "block": "ruby_ore", "minDepth": 75, "maxDepth": 1000000, "size": 5, "rarity": 0.5, "in": ["stone", "deepstone"] } ],
  "scripts":  [ { "lang": "js", "file": "main.js" } ]
}
```

| Поле | Что | Правила |
|---|---|---|
| `id` | имя мода | латиница в нижнем регистре, цифры, `-`, `_`; 2–32 знака. Становится пространством имён: блок `ruby_ore` мода `ruby-glow` = `ruby-glow:ruby_ore` |
| `name` | название | до 40 знаков |
| `version` | версия | `1.0.0` (до 4 чисел, можно `-beta`) |
| `game` | для какой игры | `"tiles"`, `"voxel"` или `"both"`; мод другой игры не устанавливается |
| `api` | версия API скриптов | сейчас `1` (можно не писать); мод с API новее игры не устанавливается |
| `author`, `description` | автор, описание | до 40 и 400 знаков |
| `textures` | картинки | `{ имя: картинка }`, см. ниже |
| `blocks[]` | блоки | до 64 |
| `items[]` | предметы | до 128 |
| `recipes[]` | рецепты | до 256 |
| `worldgen[]` | генерация мира | до 16 |
| `scripts[]` | скрипты | до 4 |

Лишние поля игнорируются (так более новые моды открываются в старой игре). Поля `__proto__`, `constructor`, `prototype` — ошибка.

**Ссылки на блоки и предметы** (в `drop`, `places`, рецептах, `worldgen`): свои — по `id` («ruby»), встроенные — по ключу
игры («stone», «torch», «bar_silver», «workbench»…), блок или предмет другого мода — полным именем («starfall:stardust»).

### textures — картинки

- `"data:image/png;base64,…"` — PNG прямо в mod.json;
- `"textures/ruby.png"` — файл из архива или папки;
- `{ "draw": { "pattern": "ore", "base": "#6f6f7a", "color2": "#e0204a", "color3": "#ffb0c0" } }` — нарисовать кодом игры.
  Узоры блоков: `dirt stone sand snow ice strata ore obsid planks brick glass leaves crystal glowshroom torch mushroom lamp`;
  узоры предметов: `pick axe hammer sword bow arrow wand bar gem gel fiber membrane feather bottle potion mushroom heart star bait lure amulet boots wings`.

Размер картинки блока — любой, игра сама ужмёт до своей клетки (в «Подземье» 16×16, пиксельно).

### blocks[] — блоки

| Поле | По умолчанию | Что |
|---|---|---|
| `id`, `name` | — | имя (латиница) и название |
| `texture` | = `id` | имя из `textures` (нет — серый блок) |
| `hardness` | 60 | прочность (земля 40, камень 100, золото 190, обсидиан 260) |
| `tier` | 0 | какая кирка нужна: 0 любая, 1 медная (камень, медь, железо), 2 железная (серебро, золото), 3 золотая, 4 глубинная, 5 огненная |
| `tool` | `"pick"` | `"pick"`, `"axe"`, `"hammer"` или `"any"` (рукой, сразу) |
| `solid` | `true` | твёрдый (`false` — сквозь проходят: лампы, украшения) |
| `transparent` | `false` | пропускает свет |
| `light` | нет | свечение: `"#ff4060"` или `[r, g, b]` (0…255) |
| `drop` | сам блок | что выпадает (`""` — ничего) |
| `falls` | `false` | сыплется, как песок |
| `climbable` | `false` | можно лезть, как по верёвке |

### items[] — предметы

| Поле | Что |
|---|---|
| `id`, `name`, `texture` | как у блоков |
| `stack` | сколько в одной ячейке (1…999, по умолчанию 99) |
| `places` | ставит блок этого мода (`"ruby_lamp"`) |
| `tool` | `{ "type": "pickaxe" \| "axe" \| "hammer", "power": 50, "tier": 2, "speed": 0.25 }` |
| `weapon` | `{ "damage": 24, "speed": 0.27, "reach": 2.9 }` — меч |
| `heal` | лечит при использовании (1…200) |
| `use` | `true` — при использовании скрипту приходит событие `use` |

Блок без своего предмета получает предмет автоматически (то же имя и картинка).

### recipes[] — рецепты

`{ "result": "ruby_lamp", "count": 2, "ingredients": [["ruby", 1], ["torch", 2]], "station": "workbench" }`;
`station` — `"workbench"` (верстак), `"furnace"` (печь), `"anvil"` (наковальня) или нет (руками).

### worldgen[] — генерация

Глубина — в **метрах ниже уровня поверхности** (как глубиномер в игре).
- `{ "type": "ore", "block": "ruby_ore", "minDepth": 75, "maxDepth": 1000000, "size": 5, "rarity": 0.5, "in": ["stone", "deepstone"] }` —
  жилы в блоках из `in`; `size` — размер жилы (2…24), `rarity` — 0,01 редко … 1 часто.
- `{ "type": "scatter", "block": "glow_flower", "minDepth": 0, "maxDepth": 20, "chance": 0.02, "on": ["grass"] }` — по одному
  на пустых клетках поверх блоков из `on`.

Генерация модов работает только в **новых** местах мира (уже сохранённые чанки не меняются).

### scripts[] — скрипты

`{ "lang": "js", "file": "main.js" }`, `{ "lang": "lua", "file": "main.lua" }` или `{ "lang": "js", "code": "…" }`.
Язык по расширению файла: `.js` — JavaScript, `.lua` — Lua, `.java` — Java (переводчик сайта js/engine/lang-java.js, тот же
API: `mod.on("chat", e -> player.message("…"))`, `System.out.println` — в журнал мода; в «Кубомире» язык подключён одной строкой —
таблица `LANGS` в `js/engine/voxel-mods.js`, файл языка грузится, только если мод на нём; фасад Fabric/Forge — docs/JAVA.md).

## 3. Скрипты: API версии 1

Скрипт работает в **закрытой песочнице**: отдельный поток в iframe без сети (CSP `connect-src 'none'`), без страницы, сайта,
аккаунта и localStorage. С игрой — только через объекты ниже. Каждое действие игра проверяет.

```js
// JavaScript
mod.on('tileBreak', e => { if (e.tile === 'ruby-glow:ruby_ore') fx.particles(e.x + 0.5, e.y + 0.5, 'spark', 16, '#ff4060'); });
commands.add('рубины', 'сколько рубинов добыто', args => player.message('…'));
npc.addLine('Глубже 75 метров попадаются рубины!');
```
```lua
-- Lua (как Luau в Roblox): те же объекты, вызовы через точку
mod.on("tick", function(e)
  if world.isNight() then player.message("Ночь!") end
end)
```

| Объект | Что есть |
|---|---|
| `mod` | `on(событие, функция)`, `log(…)` (журнал мода), `id`, `api` |
| `world` | `get(x, y)` → имя блока или `"air"` / `null` (вне окна), `wall(x, y)`, `liquid(x, y)` → `"water"` / `"lava"` / `null`, `set(x, y, имя)`, `setWall(x, y, имя)`, `isNight()`, `time()` (0…1), `day()`, `view()` → `{ x0, y0, w, h }` |
| `fx` | `particles(x, y, вид, сколько, "#цвет")` (виды: `spark magic fire smoke dust heart water star`), `sound(имя, громкость)`, `text(x, y, текст, "#цвет")`, `shake(0…1)` |
| `npc` | `say(текст)` — Проводник говорит сейчас, `addLine(текст)` — новый совет Проводника |
| `commands` | `add(имя, описание, функция(args))` — команда в чате игры: `/имя` |
| `player` | `x`, `y` (ноги), `hp`, `maxHp`, `give(предмет, n)`, `heal(n)`, `message(текст)` |
| `game` | `time`, `night`, `day`, `spawn(моб, x, y)` |
| `print(…)` | то же, что `mod.log` |

**События** (`mod.on`; можно и с приставкой `on`: `onTileBreak`, `onTick`…):

| Событие | Когда | Поля `e` |
|---|---|---|
| `start` | мир открылся | — |
| `tileBreak` | блок сломан | `x, y, tile` |
| `tilePlace` | блок поставлен | `x, y, tile` |
| `use` | использован предмет мода с `"use": true` | `item, x, y` (прицел) |
| `tick` | дважды в секунду | `dt` (0,5) |
| `mobKill` | моб побеждён | `mob, x, y` |
| `pickup` | предмет подобран | `item, n` |
| `talk` | заговорили с Проводником | `npc` |

Команды приходят в функцию из `commands.add`.

**Окно мира.** `world.get` читает «окно» вокруг события: 33×33 клетки вокруг сломанного/поставленного блока, 65×49 вокруг
игрока в `tick` и командах. За окном — `null`. `world.set` сразу меняет окно (следующий `get` видит новое).

**Ограничения** (иначе мод выключается, игра продолжается):
- не больше 400 действий (`set`, `particles`, …) за одно событие и 600 в секунду — лишние пропускаются, в журнал — ошибка;
- `world.set` — только в 64 клетках от игрока, не трогает предметы из нескольких клеток (сундуки, двери, станки);
- `player.give` — только предметы своего мода и простые: земля, камень, дерево, факел, гель, песок, стекло, платформа, верёвка, гриб;
- `player.heal` — до 50 и не чаще раза в 0,5 с; `game.spawn` — обычные мобы (не боссы), рядом с игроком;
- зависание (поток не отвечает 3 с) или 5 ошибок — мод выключается до перезапуска мира.

## 4. Моды в мире

- Моды ставятся в браузер («🧩 Моды»: из файла, из папки, примеры) и **включаются для каждого мира отдельно** — при создании
  мира или в паузе → «🧩 Моды мира» (мир перезапустится).
- Номера блоков модов хранятся в мире (`palette`), поэтому сохранения не ломаются от порядка модов. Мод удалили — его блоки
  в мире становятся пустотой, предметы — «неизвестными» (вернёте мод — вернутся).
- Мод — для игры у себя: в таблицу рекордов сайта и награды он не влияет сверх обычных лимитов сайта.

## 5. Примеры

- `mods/podzem/ruby-glow/` — «Светящиеся рубины» (JavaScript, `game: both`): руда в генерации, светящиеся блоки, лампа,
  меч, рецепты, события `tileBreak` / `tilePlace` / `tick`, команда `/рубины`, совет Проводнику.
- `mods/podzem/starfall/` — «Звездопад» (Lua): ночью падают звёзды (`tick` + `world.set`), звёздная пыль лечит (`use`),
  команда `/звезда`.

Проверка без браузера: `node scripts/tiles-test.cjs mods,sandbox` (mod.json, zip, песочница, Lua).

## 6. «Подземье» (2D, `game: "tiles"`) — особенности

- Клетка — 16×16 пикселей; 1 клетка = 0,5 м (глубина в `worldgen` — в метрах ниже уровня поверхности, уровень = 200 клеток).
- Блоки модов — номера 160…254 (до ~95 блоков модов в одном мире).
- Свет блока — цветной (`light`), гаснет на 15/255 за клетку воздуха и ~44 — камня.
- Мобы для `game.spawn`: `slime`, `blueslime`, `purpleslime`, `zombie`, `bat`, `crawler`, `imp`.
- Звуки для `fx.sound`: `coin pickup hit break click jump land buzz door_wood_open door_wood_close build_wood build_metal dig digstone place swing magic roar shoot splash squish craft levelup drink`.
- Встроенные ключи блоков и предметов — `TILE_LIST` и `defItem` в js/games/podzem-core.js.

## 7. «Кубомир» (3D, `game: "voxel"`) — особенности

«Кубомир» (#/games/kubomir) — бесконечный мир из кубиков. Код: js/engine/voxel-mods.js (проверка mod.json, zip, реестр,
песочница), js/games/kubomir-mods.js (окно «🧩 Моды»). Моды ставятся в меню миров → «🧩 Моды» (файл `.d37mod`, `.zip`,
`mod.json`, папка или перетаскиванием) и включаются для мира при создании или в игре: меню → «🧩 Моды мира» → «🔄 Применить».
Мод `"both"` ставится в каждую игру отдельно. Примеры в игре — «📦 Примеры» (кнопка «📤» скачивает файл мода);
«Светящиеся рубины» из mods/podzem (`both`) работают и здесь. Моды мира попадают в файл мира (`📤 Сохранить файл мира`).

### Как общие поля переводятся в кубический мир

| Поле | В «Кубомире» |
|---|---|
| `hardness` | секунды ломания рукой = hardness × 0,015 (камень 100 → 1,5 с, обсидиан 260 → 3,9 с); `-1` — не ломается |
| `tier` | какая кирка нужна: 0 — любая (или рука), 1 — деревянная, 2 — каменная, 3 — железная, 4 и 5 — алмазная |
| `tool` | `pick`, `axe`, `any` (рукой); `hammer` = кирка; своё: `shovel`, `sword` |
| `light` | свет белый: яркость 0…15 = самый яркий канал цвета («#ff4060» → 15, «#901028» → 8); можно и числом 0…15 |
| `transparent`, `solid`, `falls`, `climbable` | как в общей части (несплошной куб — сквозь него проходят) |
| `stack` | до 64 |
| `tool` предмета | скорость = `power` / 10 (медная кирка «Подземья» 35 → 3,5, каменная здесь — 4), `tier` 1…4, своё: `durability` (по умолчанию 60 / 130 / 250 / 1000 по tier), `damage` |
| `weapon` | меч: урон = damage × 20 / 45 (зомби «Подземья» — 45, здесь — 20); своё: `durability` |
| `heal` | здоровье здесь 20 (10 сердечек): лечит heal / 5 (50 → 10), предмет тратится |
| `use: true` | правая кнопка с предметом в руке — событие `use` своему моду (и в воздух, и по блоку) |
| рецепты | `ingredients` раскладываются в сетку (до 9 штук); `station` `workbench` / `anvil` или больше 4 предметов — только на верстаке, `furnace` — печь (на входе один предмет, `count` — сколько выйдет) |
| `worldgen` | глубина — от уровня моря (y = 52), 1 м = 1 блок; до 44 м — метр в метр, глубже мир кончается — сжато ко дну (y 8 → 2: руда «глубже 75 м» будет у самого дна); `rarity` × 8 = жил на чанк 16×16; `in` / `on` — блоки кубического мира; `scatter` с `minDepth` больше 2 — в пещерах (на блоке из `on`, если над ним воздух), иначе — на поверхности |

Ключи «Подземья», которых здесь нет, заменяются похожими (`wood` → доски, в рецептах — любые доски `#planks`; `gel` → слизь;
`workbench` → верстак; `deepstone` → камень; `bar_iron` / `bar_gold` → слитки; `rope` → лестница), остальные — пропускаются с
предупреждением (рецепт на `bar_silver` просто не появится). Генерация модов появляется и в уже открытых местах мира: мир
хранит только правки игрока, остальное каждый раз строится по зерну.

### Свои поля кубического мира (2D-игра их пропускает)

- блок: `faces` — текстуры граней `{ "top", "side", "bottom", "front" }` (`texture` — для 2D и запасная); `shape` — `cube`,
  `cross` (растение крестом), `torch`, `ladder`, `cactus`, `chest`; `sound` — `stone wood dirt grass sand gravel snow glass metal wool`;
  `bounce` — подбрасывает (скорость до 30, батут игры — 15), `hurt` — урон в секунду при касании, `slip` — скользкость (лёд 0,9),
  `replaceable` — ставится поверх, `axis` — поворачивается как бревно, `tint` — цвет биома (`grass`, `foliage`, `birch`,
  `spruce`; текстура — серая), `ui` — `craft` (верстак) / `chest` (сундук), `fuel` — секунд в печи, `lightBlock` — гасит свет (0…15);
- предмет: `food` — `{ "hunger": 4, "saturation": 2.4 }`, `fuel`;
- рецепт: `pattern` + `key` — по форме, как на верстаке (`["RRR", " | ", " | "]`, пробел — пусто), `mirror: false` — без зеркала.
  Для мода `"both"` пиши и `ingredients` — их возьмёт 2D-игра;
- `features[]` — генерация по высоте y и биомам: `ore` (`minY`, `maxY`, `size`, `perChunk`, `replace`), `scatter` (`on`,
  `chance`), `boulder` (`radius`, `radiusVar`), `column` (`min`, `max`, `top`), `tree` (`log`, `leaves`, `min`, `max`, `radius`);
  везде `biomes` (`ocean beach plains forest birch desert snow mountains swamp river`) и `perChunk` (можно дробное);
- текстура `{ "draw": { "k": … } }` — рисунки движка напрямую: `noise ore planks log log_top leaves grass_side bricks glass stripes checker dots
  stick tool ingot gem lump food feather plant torch ladder door lamp cobble`; узоры общего формата переводятся в них сами;
- `minecraft` — `{ "blocks": { "мод:блок": "свой_блок" } }`: как ставить блоки Minecraft (ванили или чужого мода) из построек и
  миров при переносе (см. «Перенос из Minecraft»). Импорт мода `.jar` заполняет это поле сам.

### Скрипты в 3D

API — тот же, версии 1 (`mod`, `world`, `fx`, `npc`, `commands`, `player`, `game`, `print`), но координаты — **x, y, z**:
`world.get(x, y, z)`, `world.set(x, y, z, "блок")`, `world.liquid(x, y, z)`, `fx.particles(x, y, z, вид, сколько, "#цвет")`,
`fx.text(x, y, z, текст)`, `game.spawn(моб, x, y, z)`. Вызов как в 2D (без z: `fx.particles(x, y, "spark", 16)`) тоже работает —
на глубине игрока. `world.time()` — 0…1, `world.view()` → `{ x0, y0, z0, w, h, d }`. Окно мира — 17×17×17 вокруг места
события, 25×17×25 вокруг игрока (`tick`, команды). Стен (фона) нет: `world.wall` → `null`, `world.setWall` ничего не делает.
Проводника нет: `npc.say` — строка в чат, `npc.addLine` принимается, `talk` не приходит.

- События: `start`, `tileBreak` и `tilePlace` (`x, y, z, tile`), `use` (`item, x, y, z, tile` — блок под прицелом или `""`),
  `tick` (дважды в секунду, `dt` = 0,5), `mobKill` (`mob, x, y, z`), `pickup` (`item, n`). Свои: `stepOn` — игрок встал на блок
  или зашёл в него (`x, y, z, tile`; нужно указать блок: `mod.on("stepOn", "spring", f)`; не чаще раза в 0,3 с), `chat` — сообщение
  в чат (`text`). У события есть и `e.player`.
- `mod.on(событие, "на что", функция)` — с фильтром по блоку или предмету (своё — коротко, «spring»; игры — как есть); с фильтром
  `use` срабатывает и на блоках («правая кнопка по моему блоку»). В `e.tile` и `e.item` имена полные (`rubies:ruby_ore`).
- Свои объекты: `mod.storage.get / set / remove` — память мода в мире (до 64 КБ, сохраняется с миром), `mod.wait(сек)` (в Lua —
  `task.wait`), `mod.command(имя, f)` = `commands.add`; `world.read(x, y, z)` — блок где угодно в загруженном мире (с ожиданием;
  в Lua ждёт само), `world.hours()` — часы 0…24; `player.z`, `.food`, `.name`, `.mode` (`survival` / `creative`), `.item` (что в руке),
  `.sneaking`; `player.hurt(n)`, `player.launch(vx, vy, vz)` (до 30; после толчка — приземление без урона), `player.teleport(x, y, z)`
  (до 128 блоков, только в загруженный мир).
- Звуки `fx.sound` — общий список (заменяются похожими) и звуки игры `kb_bounce kb_pop kb_place kb_eat kb_moo kb_oink kb_cluck kb_groan kb_squish`.
  Мобы `game.spawn` — `cow pig chicken zombie slime` (`blueslime`, `purpleslime` → `slime`; в «Мирно» враги не появятся).
- Ограничения — как в общей части: 400 действий за событие и 600 в секунду; `world.set` — до 64 блоков от игрока, не трогает и не
  ставит сундуки, печи, верстаки и двери; `player.give` — свои предметы и простые: земля, камень, булыжник, песок, стекло, факел,
  лестница, палка, слизь, доски, брёвна (и ключи «Подземья» `wood`, `gel`, `rope`, `platform`); `player.heal` — до 10 (здоровье 20) и
  не чаще раза в 0,5 с; `player.message` — 2 в секунду. Ещё: ошибка при запуске (опечатка в коде) — мод выключается сразу, с
  файлом и строкой; обработчик дольше 0,25 с пять раз — тоже. Журнал каждого мода — в игре: меню → «🧩 Моды мира».

Проверка без браузера: `node scripts/voxel-test.cjs` (часть «моды»: формат, zip, реестр, генерация, песочница JS и Lua, лимиты).

## Каталог и распространение модов (замысел, владелец 15.10.2026)
Владелец: «каждый мод получает свой номер и хранится у автора — на его компьютере, на GitHub или в другом месте — и
загружается через компьютер, но так, чтобы не было вирусов и вредных файлов». Как с Unity-играми: сайт файлы модов НЕ
хранит, только карточку и ссылку.

**Номер и карточка.** В каталоге (своя таблица, модерация как у ugc) у мода есть:
- номер (#10234) и имя `автор:мод`;
- версии (1.2.0);
- игры: podzem / kubomir / both;
- возрастная метка;
- описание, картинки, оценки, жалобы;
- зависимости;
- **для каждой версии — адрес файла и SHA-256 содержимого.**

**Где лежит файл:**
- у автора: репозиторий GitHub с тегом версии. Скачиваем через jsDelivr — `cdn.jsdelivr.net/gh/<автор>/<репо>@<тег>/…`: файл
  не меняется и отдаётся с CORS;
- любой https-адрес с CORS;
- или просто файл с компьютера игрока — без каталога, с пометкой «не проверен».

**Установка:** браузер скачивает файл и сверяет SHA-256 с каталогом. Не совпало — не ставим: автор подменил файл, а новая
версия = новая проверка. Мод кладётся в IndexedDB игрока.

**Почему вирусов не будет:**
1. **Мод — не программа для компьютера.** Внутри только данные (JSON), картинки, звуки и скрипты JS / Lua / Java, которые
   исполняет игра. Файлы .exe, .dll, .bat и прочее — отбрасываются. Код .jar не запускается: из него берутся только
   данные.
2. **Скрипты работают в песочнице.** Отдельная рамка (iframe) с запретом сети (CSP) → поток (Worker). У скрипта нет доступа к
   сайту, аккаунту, cookie, файлам, другим вкладкам и интернету; есть лимиты действий и времени. Завис или наделал ошибок —
   выключен, игра работает.
3. **Проверка файлов при загрузке:**
   - только разрешённые типы;
   - лимит размера, числа файлов и размера после распаковки (защита от zip-бомб);
   - пути без `../`;
   - JSON — по схеме;
   - картинки перекодируются (canvas → PNG/WebP), звуки — проверяются декодером.
4. **Разрешения в mod.json** («меняет блоки», «свой интерфейс», «звуки») показываются игроку перед установкой, как у
   расширений браузера.
5. **Модерация каталога:**
   - автоматическая проверка: размеры, запрещённые конструкции в скриптах, мат в текстах;
   - модератор;
   - жалобы: 3 — мод скрыт до проверки;
   - бан автора.

   Картинки нарушают правила? Это не «вирус», а содержимое — решают модерация и возрастная метка.

**Жалобы — чьи считаются и как не дать их накрутить** (владелец: «а чьи жалобы? а если постоянно будут кидать?»):
- **Кто может пожаловаться:**
  - только вошедший аккаунт старше 7 дней и с уровнем 5+ (или поддержавший), не забаненный;
  - жаловаться можно только на мод, который сам поставил или в который играл (сервер записывает установки);
  - одна жалоба от аккаунта на версию мода, причина — обязательно из списка.
- **Причины разного веса:**
  - «вредит игре», «неприличное / не по возрасту», «украден чужой мод» — идут в счёт скрытия;
  - «не работает» и «скучно» — это не жалоба, а отзыв автору: мод из-за них не скрывается.
- **Вес по доверию:**
  - у каждого есть «доверие к жалобам»;
  - модератор подтвердил жалобу — доверие растёт, отклонил как ложную — падает;
  - после нескольких ложных жалобы человека перестают учитываться, а частые ложные дают запрет на жалобы на срок;
  - у новичков вес меньше.
- **Твинки:** жалобы с одного интернета или устройства (хеши, как в приглашениях) считаются как ОДНА.
- **Порог скрытия:**
  - не «3 штуки», а сумма весов от разных людей;
  - у популярных модов порог выше (растёт с числом установок);
  - мод с отметкой «✓ проверен модератором» жалобами не скрывается — только поднимается в очереди модератора.
    Исключение — «вредит игре» от людей с высоким доверием.
- **Лимиты:** не больше 5 жалоб в сутки на человека. Если кто-то массово жалуется на моды одного автора, это видно
  модератору как возможная травля.
- **Автор:**
  - видит число жалоб и причины, но не кто жаловался;
  - получает уведомление и может обжаловать;
  - после отклонённых жалоб мод возвращается сам.
- **То же правило** — для всех жалоб на сайте: игры «Студии игр», миры, сообщества, реклама, моды. Сделать общим серверным
  модулем (доверие, вес, порог), а не в каждом файле по-своему.

**В коопе:** хозяин мира шлёт гостям номера и SHA-256 своих модов. Гость ставит их из каталога (или получает от хозяина) и
сверяет хеш. Непроверенный мод хозяина — у гостя вопрос «Разрешить?».

## Перенос из Minecraft

В «Кубомире»: меню миров → **📥 Из Minecraft** (или «🧩 Моды» → «⛏ Импорт из Minecraft», или в игре: Esc → «📥 Импорт из
Minecraft»). Файл можно перетащить в окно. Всё переводится **один раз**, при импорте; файлы Minecraft не уходят на сайт и
хранятся только в браузере игрока (IndexedDB). «Кубомир» не связан с Mojang и Microsoft: он читает форматы файлов, а
картинок Minecraft у сайта нет — их приносит сам игрок (пакет текстур).

| Что | Файлы | Что получится |
|---|---|---|
| Постройка | `.schem` (WorldEdit/Sponge v1–3), `.schematic` (MCEdit), `.litematic`, `.mcstructure` (Bedrock), `.nbt` (структурный блок), `.zip` с ними | новый мир с постройкой на площадке или «🏗 Поставить перед собой» в открытом мире |
| Мир Java | `.zip` папки мира (`region/*.mca` + `level.dat`) или один `.mca` | новый мир из выбранной области: карта чанков, размер до 528 × 528, окно высоты (мир «Кубомира» — 128 блоков; по умолчанию уровень моря совпадает) |
| Мир Bedrock | `.mcworld` | то же, «как получится» (LevelDB; подчанки формата 8/9) |
| Пакет данных | `.zip` с `data/…` | мод: рецепты (по форме, без формы, печь), функции `.mcfunction` → скрипт (команды `/function пакет:имя` и по именам, `tick`/`load`) |
| Дополнение Bedrock | `.mcaddon`, `.mcpack` | мод: блоки, предметы, рецепты, добыча, функции, скрипты `@minecraft/server`; картинки ванили из пакета ресурсов — пакетом текстур |
| Мод Java | `.jar` | мод **только из данных**: блоки (по моделям и blockstates), предметы, переводы (ru_ru, en_us), рецепты, добыча, теги «чем копать» |
| Пакет текстур | `.zip` Java (`assets/minecraft/textures`) или Bedrock (`textures/blocks`) | картинки поверх своих во всех мирах (приводятся к 16 × 16); убрать — там же |

**Блоки.** Таблица `js/engine/mc-map.js`: знакомые блоки — на свои (ось бревна, сторона факела, лестницы, печи, двери);
ступени, плиты, стены, заборы — целым блоком своего материала; тонкое (ковры, кнопки, рельсы, таблички, цветы) пропускается;
блоков, которых нет (шерсть, бетон, терракота, медь…), «Кубомир» делает сам — цветной кубик (`mc:имя`; с пакетом текстур — с его
картинкой); незнакомые — розово-чёрные (`missing`), их список — в отчёте. Течение воды и лавы убирается (потечёт само из
источников). Блоки модов: поле `minecraft` в mod.json (импорт `.jar` и дополнений заполняет его сам) — поставь мод, и
постройки с его блоками перенесутся.

**Функции (.mcfunction)** — что работает: `say`, `tellraw`, `title`, `give`, `setblock` (`keep`), `fill` (`replace`, `keep`,
`hollow`, `outline`), `tp`/`teleport`, `scoreboard objectives add`, `scoreboard players set/add/remove/reset`, `function`,
`summon` (зомби, скелет, паук, крипер, слизень, свинья, корова, курица, овца), `particle`, `playsound`, `execute` — `as`/`at`
(игрок), `positioned`, `if`/`unless block`, `if`/`unless score … matches`, `if entity` и `run`. Координаты `~` — от игрока.
Остальное становится комментарием и попадает в отчёт. Ограничения песочницы те же: 400 действий за событие, 600 в секунду,
`world.set` — до 64 блоков от игрока, `give` — свои и простые предметы.

**Скрипты Bedrock (`@minecraft/server`)** — модули собираются в один скрипт, к нему добавляется свой слой «@minecraft/server»
поверх API модов: `world.afterEvents` (`playerBreakBlock`, `playerPlaceBlock`, `chatSend`, `itemUse`, `itemUseOn`,
`playerInteractWithBlock`, `playerSpawn`, `worldInitialize`/`worldLoad`, `entityDie`), `world.sendMessage`, `getPlayers`,
`getDimension().getBlock(…)` → `typeId`, `setType`, `above/below`, `world.scoreboard` (цели и очки), `get/setDynamicProperty`,
`system.run`, `runTimeout`, `runInterval`, `clearRun`, игрок (`name`, `location`, `sendMessage`, `teleport`, здоровье, вещи),
`ItemStack`, `BlockPermutation`. Формы `@minecraft/server-ui` открываются как «закрыто», `runCommand` — нет. Песочница та же.

**Моды Java (.jar).** Код мода (`.class`, Fabric/Forge/NeoForge) в браузере не запускается и не переводится — переносятся
данные. Поведение (что блок делает, когда его ломают, кликают, наступают) можно переписать скриптом мода: JavaScript, Lua или
Java (тот же API: `mod.on("tileBreak", …)`, `world.set(…)`, `player.give(…)`). Свет блока
берётся по имени (lamp, lantern, glow, light, torch…), прочность — по виду (руда, дерево, земля…), инструмент — из тегов
`mineable/*` и `needs_*_tool`. Большой мод делится на части (в общем формате — до 64 блоков, 128 предметов, 256 рецептов) —
включай части вместе.

**Как проверить:** `node scripts/mc-import-test.cjs` — образцы всех форматов собираются в самом тесте (без файлов Mojang).
