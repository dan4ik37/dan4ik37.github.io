# Новые функции: XP и уровни, лента Shorts, страницы видео для поисковиков, доска идей

Дата: 2026-09-27. Статус: согласовано и реализовано (порядок изменён владельцем: страницы видео → Shorts → идеи → XP).

## Зачем

Цель владельца: больше подписчиков и просмотров YouTube (доход с рекламы YouTube), приток новых людей,
желание возвращаться на сайт. Каждая функция проверяется этим вопросом:

| Функция | Что даёт |
|---|---|
| XP и уровни | повод заходить каждый день, регистрироваться и смотреть видео **на сайте** (встроенные просмотры засчитываются каналу) |
| Лента Shorts | «залипание»: много просмотров подряд за один визит |
| Страницы видео `/v/<id>` | сайт начинает находиться в Google/Яндексе по названиям роликов; ссылки «поделиться» ведут на сайт |
| Доска идей | вовлечение аудитории + готовые темы для роликов |

Предлагаемый порядок работ: **Shorts → Доска идей → XP → Страницы видео**. Shorts и доска быстрые и сразу видны;
XP опирается на доску идей (награда за принятую идею); страницы видео не зависят от остальных.

## 1. Лента Shorts (`#/shorts`)

- Полноэкранная вертикальная лента со scroll-snap (свайп/колесо = следующий ролик), как в TikTok.
- Источник — уже загружаемые `newestVids` (youtube.js). Short = в названии `#shorts` **или** длительность ≤ 3:00.
  YouTube API не отдаёт признак «это Short», поэтому эвристика; ошибка в худшем случае покажет короткий обычный ролик.
- iframe создаётся только для ролика на экране (IntersectionObserver), уходящий с экрана — выгружается.
  Одновременно играет один. Кнопки поверх: лайк (открывает YouTube), «Подписаться», «Поделиться», звук.
- На главной — ряд «Shorts» (горизонтальная карусель превью) → открывает ленту с нужного ролика.
- Пункт «Shorts» в меню и в нижнем таб-баре на телефоне (вместо «Донат» — донат остаётся в меню и FAB).
- Если Shorts не нашлось — раздел не показывается в меню.

## 2. Доска идей (`#/ideas`)

- Таблицы `ideas` (автор → `profiles`, заголовок ≤ 120, описание ≤ 500, статус `new|planned|done|rejected`,
  `video_id` для «сделано — вот ролик», `created_at`) и `idea_votes` (idea_id, user_id — уникальная пара).
- Предлагать и голосовать — только вошедшим (ещё один повод зарегистрироваться). Гостям видно всё, кнопки ведут на вход.
- Защита на стороне БД (RLS + триггер): не больше 3 идей в сутки на человека; статус и `video_id` меняет только admin;
  голосовать можно только за себя, один раз.
- Сортировка: «Топ» (по голосам) / «Новые»; фильтр по статусу. Для «Сделано» — ссылка на ролик.
- Админ меняет статус прямо в карточке (кнопки видны только admin).
- Файл миграции: `ideas.sql` (идемпотентный, отдельный — как принято в проекте).

## 3. XP и уровни

**Хранение:** журнал `xp_ledger(user_id → profiles, source, ref, amount, day, created_at)` с уникальным
ключом `(user_id, source, ref, day)` — одна и та же награда не начисляется дважды. Начисление — только
на сервере (триггеры и security definer RPC), клиент не может записать XP напрямую (RLS: только чтение своего).

**Источники (дневные лимиты в скобках):**

| Действие | XP | Как проверяется |
|---|---|---|
| Заход на сайт за день | 10 | триггер на `user_visits` |
| Стрик 7 / 30 дней | 50 / 200 | в том же триггере |
| Просмотр видео на сайте | 5 за ролик (до 10 роликов = 50/день) | RPC `claim_watch_xp(video_id)`; клиент вызывает после ≥ 60 с воспроизведения (Shorts — ≥ 15 с) по YouTube IFrame API; сервер: уникальность ролика за день, лимит, пауза ≥ 30 с между начислениями |
| Сообщение в чате | 1 (до 30/день) | триггер на `messages` (только с `user_id`, гостям нет) |
| Тема форума / ответ | 15 / 3 (до 5 тем, 20 ответов в день) | триггеры на `forum_threads` / `forum_posts` |
| Идея предложена / сделана | 5 / 100 | триггеры на `ideas` |
| Приглашённый друг | 100 | триггер на `profiles.referred_by` |

Просмотр технически можно «накрутить» из консоли браузера, но максимум 50 XP в день — это осознанный компромисс:
честная проверка просмотра без сервера YouTube невозможна.

**Уровень:** `level = floor(sqrt(xp / 50)) + 1` (ур. 2 = 50 XP, ур. 5 = 800, ур. 10 = 4050, ур. 20 = 18 050).

**Что видно:**
- Профиль: уровень, полоска до следующего, разбивка «откуда XP» за неделю.
- Бейдж `Lv N` рядом с ником в чате, на форуме, в мини-профиле. Рамка ника по порогам 5 / 10 / 20 / 30
  (не пересекается с VIP-оформлением — VIP остаётся отдельным).
- «Топ недели по XP» в блоке «Сообщество» на главной (RPC `top_xp_week()`).
- Тост «+5 XP» после засчитанного просмотра; для гостя — «Войди, чтобы получать XP за просмотры».
- Файл миграции: `xp.sql`. Считается «с нуля»: старые сообщения/визиты задним числом XP не дают (кроме
  разового стартового бонуса: 10 XP за каждый день из `user_visits`, чтобы у активных не было нуля).

## 4. Страницы видео для поисковиков (`/v/<id>`)

- `vercel.json`: rewrite `/v/:id` → `api/video.js`. Функция на сервере берёт данные ролика из YouTube API и отдаёт
  **готовый HTML** (поисковики и превью мессенджеров не выполняют JS SPA): `<title>`, meta description,
  Open Graph с превью ролика, JSON-LD `VideoObject`, встроенный плеер, описание, кнопки «Подписаться» и
  «Больше на сайте», 8 последних роликов ссылками `/v/...` (перелинковка).
- Кэш на CDN Vercel: `s-maxage=86400, stale-while-revalidate` — квота YouTube почти не тратится.
- `/sitemap.xml` → `api/sitemap.js`: главная + `/v/<id>` последних 50 роликов (кэш 1 день).
- Кнопка «Поделиться» у видео на сайте копирует ссылку `/v/<id>` — пересланная ссылка ведёт на сайт с красивым превью.
- Невалидный id / ролик не найден → 404-страница в стиле сайта со ссылкой на главную.

## Общие правила

- SQL — отдельные идемпотентные файлы (`ideas.sql`, `xp.sql`); владелец запускает их в Supabase SQL Editor.
  Пока файл не запущен, соответствующая часть сайта скрывается и не показывает ошибок.
- Все анимации — только под `body.high`, как во всём сайте.
- Проверка: локальный сервер + браузер (ПК и 375 px) для фронтенда; SQL — ревью (доступа к БД с правами
  на DDL нет); серверные функции — локальный вызов handler'а с подставленным запросом.
- Каждая функция — отдельный коммит и деплой, чтобы сломанное можно было откатить по одной.
