# Как сделать сумму на шкале «Сбор» настоящей — до последнего рубля

Коротко: раньше сумма на шкале считалась по последним ≤20 донатам (чинили в
прошлый раз) и по последним 14 дням (это новое ограничение, которое чиним
сейчас) — если донатов на канале накопилось больше, чем помещается в эти
рамки, часть истории сайт просто никогда не видел. Теперь есть кнопка,
которая один раз проходит ВСЮ историю донатов с DonationAlerts и досчитывает
всё, что было упущено.

## Что сделать (один раз)

1. **Выполнить обновлённый `server-hardening.sql`** в Supabase → SQL Editor.
   Можно перезапускать сколько угодно раз — проверено и с нуля, и поверх уже
   применённой у вас версии.
2. Открыть сайт под своим аккаунтом (**обязательно тем же, у которого роль
   `admin`** в базе — иначе кнопка откажет).
3. **⚙️ Настройки сайта → «Цель доната»**. При необходимости поставьте дату в
   поле «Считать донаты с даты» (пусто = вся история — обычно это и нужно).
4. Нажмите **«📜 Импортировать всю историю»**.
5. Подождите. Кнопка сама достучится до сервера нужное число раз — по
   несколько страниц донатов за раз, — и статус под ней будет обновляться:
   `Импортируем историю... страниц: N, донатов учтено: M`. Вкладку можно
   закрыть в любой момент и вернуться позже — продолжит с той же точки, а
   не с начала.
6. Готово, когда появится **«✅ Готово! Просмотрено страниц: …, донатов в
   истории: …»**. Сумма на шкале «Сбор» на странице доната тут же обновится
   и с этого момента будет полной и точной.

Кнопка **«↻ Начать импорт заново»** — на случай сбоя или если очень нужно
перепройти историю с нуля. Уже учтённые донаты при этом не задвоятся (каждый
донат учитывается по его собственному ID ровно один раз, это проверено).

## Как это работает — если интересно

- Обычная синхронизация (та, что работает сама каждые 5 минут) специально
  лёгкая: смотрит только на последние 14 дней и не больше 8 страниц за раз —
  чтобы не тормозить сайт и укладываться в секунды. Для свежих донатов этого
  всегда достаточно, но для ЦЕЛИКОМ точной суммы «сколько собрано за всё
  время» этого мало.
- Кнопка запускает отдельный, более медленный режим той же серверной функции
  (`api/vip-sync.js?backfill=1`), который идёт по истории DonationAlerts
  вглубь без ограничения по дате, страница за страницей, пока не дойдёт до
  конца. Он рассчитан на минуты, а не секунды, поэтому работает не одним
  запросом, а циклом коротких «порций» — так, чтобы ни один отдельный вызов
  не упёрся в 30-секундный лимit serverless-функции на Vercel.
- Каждый найденный донат проходит через ту же проверенную функцию
  начисления, что и обычная синхронизация — если он не первый раз (уже был
  учтён раньше), просто пропускается, без риска задвоить сумму.
- Доступ к этой кнопке проверяется сервером по вашему собственному входу в
  аккаунт (не по паролю в коде и не по секретному ключу, который мог бы
  случайно попасть в браузер) — сработает только под ролью `admin`.

## Единственное честное ограничение

Сайт может увидеть ровно то, что отдаёт API DonationAlerts. Если сам
DonationAlerts по каким-то причинам не показывает через API донат
многолетней давности — досчитать его неоткуда, это не ограничение кода,
а предел того, что вообще доступно снаружи. На практике для действующего
канала это не должно быть проблемой.
